**Corrections à des docs Mimas** : (a) DOSSIER_MATERIEL §7.2-G:614 « PowerSlave a un far clip à 1024 » — FAUX : `ENABLEFARCLIP 0` (WALLS.C:28) désactive les deux tests (WALLS.C:1460-1462, 1607-1608) ; FARCLIP F(1024) (WALLS.C:629) ne borne que les ombres de sprites. (b) DOSSIER §2.3:152 « SlaveDriver ~20 fps » n'est PAS sourçable dans l'arbre : le gouverneur ne connaît que 60/30 Hz (smoothVTime ≤ 2, SRUINS.C:2262) et laisse les frames longues dériver.

**MARGE D'OPTIMISATION DANS SLAVEDRIVER (classée gain plausible × coût ; tout est [src], rien n'a été mesuré)**

1. **Slave idle sur le prefix ET le suffix maître ; ré-émission sérielle de ≤1300 polys.** Preuve : slave ne travaille qu'entre MINIT (WALLS.C:2246) et SINIT (WALLS.C:1932) ; findDoorways/buildTree/sort (WALLS.C:1546-1795, 1953-1984, 2169-2236) et drawSlaveWalls (mapPic + EZ_specialDistSpr par record, WALLS.C:1840-1916, SPR.C:232-245) sont maître-only. Leçon Mimas : le slave ne paie que sur du compute-bound cache-chaud (RESOURCE_BUDGETS.md:126-130) — transform/light (DIVU + mac.l, WALLASM.S) l'est ; l'émission VRAM ne l'est PAS (« kick → slave = mort par arithmétique », DOSSIER §2.2:107-109) → déplacer la traversée portails N+1 sur le slave pendant le suffix, garder l'émission au maître. Gain : frame-time, inconnu tant que `time:calc/draw` n'est pas relevé console. Coût : élevé (double-buffer sectorDraw 36 Ko + doorwayCache 66 Ko, 2e handshake FRT).
2. **Équilibrage ±1 secteur/frame au seuil 100 spins.** WALLS.C:2281-2285 ; un secteur proche = jusqu'à 700 sommets/mur (WALLS.C:962) → oscillation grossière, spins maître non chiffrés. Work-stealing par `tas.b` sur updateList via alias cache-through (records portent déjà le secteur, WALLS.C:1815-1816). Gain : frame-time, inconnu. Coût : moyen. Risque : Mimas a mesuré qu'un join qui spinne non-caché ralentit le job attendu (RESOURCE_BUDGETS.md:129-130).
3. **Mipmaps gatés sur `desiredWeapon` et MIPDIST 256 ; far clip OFF.** Mips seulement si une arme est tenue (WALLS.C:1001-1004, 1282-1285) ; quad count /4 au-delà de 256 unités (PIC.C:359-387). Toujours-ON + MIPDIST abaissé = moins de cmds = moins d'émission maître (64,5 µs/cmd chez Mimas, DOSSIER:121-123) ; far clip F(1024) réactivable (WALLS.C:28) mais l'erase 0x0000 (SRUINS.C:1974) transforme tout mur coupé en ciel. Gain : frame-time (cmds), inconnu ; visuel à juger. Coût : 1-2 lignes chacune.
4. **Polygone d'effacement redondant (130/240 lignes de fill VDP1 par frame).** SPR.C:39-63 : erase HW pleine hauteur (SPR_SetEraseData 0,0,319,240) ET polygone cmd 0 lignes 110-240. SBL pose bien EWLR/EWRR (spr_1c.o SPR_Initial) — contrairement au cas slSynch de Mimas (mémoire vdp1-erase-under-slsynch). Gain : temps de plot (transfer-over = perte de contenu, RESOURCE_BUDGETS.md:221-224), inconnu jusqu'à sonde par bande sur console. Coût : trivial.
5. **Copies CPU partout où le DMA existe.** CD : 2 copies/octet (FILE.C:210/254), TMODE_CPU (FILE.C:162) ; son : 3 passes (SOUND.C:207-223) ; films USEDMA 0 (MOV.C:30) ; staging VDP1 mono-buffer avec spin avant chaque flush (SPR.C:141-157, DMA.C:84 ; ~11 flushes/frame à 1448 cmds). Gain : temps de chargement + qq centaines de µs/frame ; classe mémoire/CD, inconnu. Coût : faible. ⚠ Loi Mimas : JAMAIS de SCU-DMA vers VRAM VDP2 (freeze, RESOURCE_BUDGETS.md:143-145) — DMA.C:89-90 ne cible que le VDP1, garder ça ; PLAX.C:94 et SRUINS.C:1084 (VDP2) doivent rester CPU.
6. **Cache texture : 28 slots 64×64 16bpp pour ~800 tuiles, expansion 8→16 bpp sur CPU à chaque miss.** PIC.C:262-291 (LRU par classe), 293-317 (4096 lookups) + mip recalculé (PIC.C:363-387). Compteurs de swaps existent sous !NDEBUG (PIC.C:171-192). Leviers : mips pré-cuits dans le .LEV (+25 % RAM HWRAM par tuile), ou murs COLOR_4 palette — mais CRAM 8/8 pleine (PIC.C:625-666) et Mimas a mesuré le plafond 7 banques (RESOURCE_BUDGETS.md:248-250) ; le gouraud RGB par sommet (WALLS.C:636-677) est déjà supérieur au snap CRAM de Mimas. Gain : frame-time si thrash, inconnu (lire nmSwaps d'abord). Coût : moyen.
7. **Budgets silencieux = trous et gouraud corrompu.** Cmds tronquées (SPR.C:141-143), gouraud tronqué mais `grshAddr` déjà écrit (SPR.C:150-152), murs PROCHES abandonnés entiers (WALLS.C:1278-1279, 1380-1381). Mimas : AIMD + drop far-first (mémoire aimd-wbudget). Gain : correction, pas fps. Coût : faible (drop loin-d'abord = inverser l'ordre de garde dans slave_drawRectWall).
8. **VDP2 sous-employé : A0 ~126 Ko vides, 6/8 slots banc B libres.** PLAX.C:96/115, SRUINS.C:1052-1055. Stat bar = char VDP1 13 440 o + 1 cmd/frame + pokes CPU (SRUINS.C:1164-1202, 1322-1343) → NBG1 en A0 ; fenêtres gratuites (RESOURCE_BUDGETS.md:250-251) mais famine de cycles = NEIGE console-only (RESOURCE_BUDGETS.md:251-252) — vérifier RDBSA0 avec la K-table RBG0. Gain : ~15 Ko VRAM VDP1 + 1-3 cmds ; classe mémoire. Coût : faible.
9. **Fenêtre ciel W1 = UNION bbox** (WALLS.C:1493-1516, SRUINS.C:2277-2279) : la bande entre deux ouvertures de ciel n'est masquée que par l'overdraw VDP1 ; W0 libre hors image VDP2 (PIC.C:459). Gain : plot évité inconnu. Coût : faible.
10. **Hygiène cache/bus.** SNDBASE caché 0x05a00000 (SOUND.H:4, MOV.C:130) — reads CA/MSLC (AI2.C:389/425) potentiellement périmés sur HW ; purge cache 4 Ko complète du maître chaque frame (WALLS.C:1826-1828) au lieu de lire les records via l'alias 0x2xxxxxxx ; RMW `SECFLAG_SEEN` par le slave (WALLS.C:1428) ; double écrivain colour-offset (V_BLANK.C:114-116 vs SCL_FUNC.C:730-738). Gain : correction, µs. Coût : trivial.
11. **Chargement : sons statiques rechargés à chaque niveau, staging son en LWRAM.** SOUND.C:164, SRUINS.C:1922-1932 ; fs_read direct en RAM son déjà prouvé par AI2.C:117-135. Gain : temps CD par niveau (classe CD/mémoire). Coût : faible.

**Ce que SlaveDriver a que Mimas n'a pas (à ne pas « corriger »)** : tuiles 64×64 uniformes murs+sols ⇒ 81 slots + 1448 cmds dans 512 Ko (DOSSIER §7.2-G:609-613) ; gouraud par sommet + 15 lumières ponctuelles (WALLS.C:464-474) ; user-clip par secteur comme occlusion VDP1 (WALLS.C:2247-2253) ; JUMP_CALL/RETURN pour placer les sprites émis tôt (WALLS.C:2257-2269, SPR.C:430-458) ; gouverneur asymétrique 1↔2 vblanks (SRUINS.C:2239-2266) — le seul de ces mécanismes que Mimas puisse reprendre sans réécriture est le gouverneur (mémoire gametic-slowmotion-tic-cap).
